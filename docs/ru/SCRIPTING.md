# Проекты и скрипты в 1.3

При запуске выберите папку проекта. Сцена хранится в `project.lunoryx`, код — в `scripts/`, импортированные ресурсы — в `assets/`, снимки восстановления — рядом с манифестом. Ctrl+S сохраняет проект. Основной манифест читает код из файлов; снимок восстановления читает встроенный код на момент снимка. Кодировка — UTF-8, допустим BOM; CRLF приводится к LF. Всего до 32 документов по 65 535 байт. Имена файлов должны быть уникальны, в том числе без конфликтов регистра на Windows/macOS.

В Explorer откройте Scripts → Create… и создайте обычный или модульный скрипт Lua/Luaryx либо C#. В имени допустимы подпапки: они создаются при сохранении. Модуль Lua возвращает значение и подключается через `require("subfolder.Module")`. Поиск ограничен модульными документами этого проекта; произвольные внешние и нативные модули не загружаются. Модули C# компилируются вместе с обычными скриптами и предоставляют вспомогательные типы; их классы Script автоматически не запускаются.

Редактор поддерживает подсветку, номера строк, буфер обмена, ограниченную историю отмены кода и отметки ошибок C#. F5 запускает обычный Lua-скрипт в новом состоянии Lua либо перекомпилирует обычные C#-скрипты и их модули. Модуль подключается из обычного скрипта. F6 запускает/останавливает Play; Stop восстанавливает сцену редактора. Сохранение не перезаписывает проект временным миром Play. Восстановление сохраняет исходную сцену и текущий код: по умолчанию раз в пять секунд и после завершённых изменений сцены.

## Общие объекты

Luaryx — API поверх настоящего Lua 5.4, без нового несовместимого синтаксиса. Старые функции `add_object`, `set_position`, `get_property` и другие сохранены. Для нового кода используйте стабильные ID вместо индексов, которые меняются при удалении объектов.

```lua
local cube = luaryx.create("Shared", "cube")
cube:position(0, 1, 0)
cube:property("score", 42)
local saved_id = cube.id
local same = luaryx.get(saved_id)
luaryx.emit("from_lua", '{"score":42}')

function on_message(name, json_text)
    print(name, json_text)
end
```

`luaryx.get(id)` возвращает объект либо nil; `luaryx.find(name)` отвергает неоднозначное имя. Методы объекта: `position`, `rotation`, `scale`, `velocity`, `property` — чтение без дополнительных аргументов и запись с ними — и `destroy`. Удалённый объект выдаёт явную ошибку. Свойства хранят число, boolean или строку. Второй аргумент `luaryx.emit` и данные в Lua `on_message` — строки JSON.

```csharp
using Luaryx;
using System.Text.Json.Nodes;

public sealed class Main : Script {
    private Entity cube = null!;
    public override void OnStart() {
        cube = Scene.Find("Shared") ?? Scene.Create("Shared");
        cube.SetProperty("score", 42);
        Scene.Emit("from_csharp", JsonValue.Create(42));
    }
    public override void OnUpdate(float deltaTime) {
        cube.Position = cube.Position + new Vector3(deltaTime, 0, 0);
    }
    public override void OnMessage(string name, JsonNode? value) {
        Scene.Log($"{name}: {value}");
    }
    public override void OnTrigger(string kind, ulong zone, ulong actor) { }
}
```

В C# доступны `Scene.Get(id)`, `Find(name)`, `Create(name, primitive)`, `All`, `Emit`, `Log`. Entity предоставляет `Id`, `Name`, `Position`, `Rotation`, `Scale`, `Velocity`, `GetProperty`, `SetProperty`, `Destroy`. Ссылки сохраняются при обновлении сцены и изменении индексов; обращение к удалённому объекту вызывает ошибку. Изменения и сообщения передаются между процессами ограниченными пакетами. Быстрый пролёт через триггер может выдать enter и exit в одном такте.

## Доверие и ограничения

C# — настоящий .NET/Roslyn с доступом к файлам, процессам и сети от имени вашей учётной записи. Это **не песочница**. Для загруженного проекта требуется явное доверие на текущий сеанс. Новый проект, созданный вами, доверен в этом сеансе. Процесс останавливается при превышении времени компиляции/обновления; это защита от зависания, а не изоляция данных ОС. Ошибки приостанавливают симуляцию и показываются в диагностике.

Lua ограничен по памяти, инструкциям, библиотекам и путям ресурсов. Нативные операции моделирования/экспорта выполняются в ограниченных дочерних процессах. MCP по умолчанию разрешает чтение; для изменений нужен `--allow-write`, для Lua дополнительно `--allow-lua`.

В релиз включена среда исполнения, поэтому .NET SDK нужен только для её сборки. На Windows оставляйте `Runtime/` рядом с `Lunoryx.exe`, на macOS сохраняйте структуру `.app`. Если игра использует C#, его среда включается в сборку.
