# Schema 4 migration / Миграция schema 4

The owner approved schema changes with migration and backup. This is the storage foundation for 1.4.0; new skeleton/collider/material features are not implied. / Владелец согласовал смену формата с резервированием. Это основа хранения 1.4.0, а не завершённая реализация скелетов, коллайдеров и материалов.

Current source reads schemas 1–4 and writes schema/format 4. A provided `format_version` must agree with `schema`. Old engines may reject schema 4. Opening a project never runs scripts or writes a migration. / Читаются schemas 1–4, записывается 4; несовпадающие schema/format отклоняются. Открытие не выполняет скрипты и не записывает миграцию.

Before the first old manifest or tracked-script write:

1. Capture the old manifest and actual tracked script source from disk, before writing any new code to `scripts/`.
2. Publish `.pre-1.4.recovery.lunoryx` with self-contained tracked script source. Relative assets remain in the original folder.
3. Preserve an existing `.pre-1.3.bak`; create it for pre-schema-3 source if absent.
4. Publish the exact original manifest bytes as `.pre-1.4.bak` last. Existing names are never replaced. A partially completed pair can resume; an inconsistent pair stops the write.

До первой записи сохраняются исходные байты манифеста и текст отслеживаемых скриптов с диска. Recovery публикуется первым, точный `.pre-1.4.bak` — последним; прежние копии не перезаписываются. Незавершённую запись можно продолжить, конфликт останавливает изменение проекта.

All outputs use anchored local operations and temporary files. Windows publishes by handle-relative rename with replacement disabled; POSIX publishes a completed temporary inode with `linkat` and removes its staging name. This preserves atomic visibility and refuses existing targets. It does not claim power-loss durability for the whole multi-file save transaction.

`Open pre-1.4 recovery` opens the old scene/source without execution. Save operations refuse backup filenames; use Save Project As with another filename. The backup is not an external asset-history system. Keep the project folder/assets; untracked files are not overwritten by script synchronization or captured as document scripts. / Резервную сцену можно открыть через Open pre-1.4 recovery и сохранить под другим именем. Саму копию редактор не перезаписывает. Папку и ассеты нужно сохранять отдельно; это не история внешних изменений файлов.

`SaveCurrentProject` now refuses Play saves before synchronizing scripts. Previously the scene save failed after scripts had already been written. / Сохранение во время Play теперь отклоняется до записи скриптов.

All save entry points synchronize scripts when writing the active folder's `project.lunoryx`, including Save As/MCP. This prevents a newer embedded script from being shadowed by stale disk source on reopen. Saving a standalone copy under another filename does not synchronize the original folder. / При записи текущего `project.lunoryx` все пути сохранения синхронизируют скрипты, включая Save As/MCP: старый файл больше не подменяет новый код при повторном открытии. Отдельная копия под другим именем не записывает скрипты исходной папки.
