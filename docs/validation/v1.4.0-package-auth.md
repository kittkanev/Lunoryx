# 1.4.0 development: authenticated game packages / аутентификация игровых паков

This records the F0 package change, not completion or release of 1.4.0. / Здесь записан этап F0, а не готовность или выпуск всей версии 1.4.0.

## Patch / Изменения

- External owner-only 32-byte keys, OS randomness, exclusive creation and active-key write protection. No key in project/game metadata. / Внешний ключ из 32 байт, системный генератор, создание без перезаписи и защита выбранного ключа от записи редактором.
- `LNXPCK02`: HMAC-SHA-256 over domain, parsing-critical footer and exact consumed payload. Reject CRC-only v1, wrong/missing keys and tag failures before asset commit. / HMAC проверяет заголовок и именно используемые данные; старые CRC-паки и неверные ключи отклоняются до установки ресурсов.
- Bounded manifest/range checks, shared footer detection for PE certificates/padding, no nested runtime. Runtime/resource/output collection rejects key identities and copied raw key bytes, including across chunk/resource boundaries. / Проверки границ и защита от вложенного пака; ключ и его сырые копии исключаются из результата.
- Atomic failed output preserves existing games. Background export/model jobs finish before key/I/O policy destruction. / Ошибка не заменяет существующую игру; фоновые задачи завершаются до уничтожения состояния I/O.

## Limits and pending evidence / Ограничения и ожидаемые проверки

HMAC is symmetric: anyone with the key can forge packages. It does not authenticate/encrypt the executable, identify a publisher, prevent replay or isolate secrets from trusted C# with user OS permissions. / Владелец ключа может создавать новые паки; HMAC не подписывает EXE, не шифрует данные и не ограничивает доверенный C#.

Windows/macOS changes require fresh native CI, and the complete sanitizer rebuild remains a gate. Certificate-backed Authenticode and Developer ID/notarization have not run. The large feature backlog, schema migration and fresh 1.4.0 UI video are not completed by this patch. / Нативный Windows/macOS CI, санитайзеры, настоящая подпись, миграция и функции крупного обновления остаются отдельными задачами.

Local graphics required `MESA_SHADER_CACHE_DISABLE=true`; see [baseline diagnosis](major-update-baseline.md). This is software-Mesa evidence, not broad GPU/driver coverage.

## First fresh native run / Первый новый нативный CI

Run [44060940817](https://github.com/kittkanev/Lunoryx/actions/runs/44060940817), source `a6b99fc`, passed both native Mac architectures and universal bundle validation, plus normal Linux integration, packaged C# gameplay, budget stress, graphics and UI recording. It was **not fully successful**: MinGW rejected a lambda capturing a CRT-specific unique_ptr type with greater visibility; capture now uses the borrowed `FILE*` while retaining RAII ownership. UBSan rejected `fwrite(nullptr, 1, 0)` in the empty-key fixture; zero-byte writes now skip stdio in direct/atomic/new-file modes.

The corrected I/O header passed a fresh standalone `g++ -std=c++17 -fsanitize=address,undefined` build and run of `tests/asset_io_tests.cpp`, with leak checks and halt-on-error enabled. The full replacement CI is still required. The sanitizer integration step now explicitly selects the real C# worker instead of allowing its tests to skip because the test executable lives in `tests/`.
