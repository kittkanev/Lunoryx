# Lunoryx Studio 1.1.0-experimental.1 — эксперимент скорости и рендера

Pre-release с измеряемыми изменениями отрисовки, физики и Weld. Прежняя тема Studio, докинг, Explorer, Properties, Tools и вкладки кода сохранены. Стабильный Latest остаётся **1.0.1**.

## Что изменилось

- **Кэш отрисовки и отсечение.** Подготовленная геометрия хранится в кэше и отправляется через VBO, с группировкой по материалу. Объекты вне камеры отсекаются по кэшированным границам. Это сокращает повторные вызовы OpenGL на каждую грань и вершину. Если VBO недоступен, используется путь через массивы вершин. Изменения геометрии обновляют кэш; переключатель Cached renderer позволяет сравнить результат с прежним путём.
- **Физика.** Границы объектов рассчитываются и кэшируются в пределах физического шага; после разрешения контакта обновляются границы перемещённых объектов. Порядок пар и разрешения AABB-столкновений сохранён. Дифференциальные проверки сравнивают результат с 1.0.1 побитово.
- **Rust только в выбранном участке.** Пространственный поиск соответствий Weld / Merge by Distance используется при выборе от 512 вершин. Для малых выборок и координат вне допустимого диапазона пространственной сетки сохранён C++ путь. Остальная обработка топологии, редактор и Lua не переписаны. CRC32 и расчёт границ остаются на C++: контрольные замеры не показали оснований для переноса.
- **Настройки рендера.** F8 переключает Office, Balanced и Quality в редакторе и готовой игре. Settings содержит Render preset, Render scale и Cached renderer. Можно отдельно выбрать нагрузку на GPU и разрешение 3D-сцены.
- **Постобработка и тени.** Balanced добавляет FXAA, Quality — FXAA, LDR-коррекцию цвета с экспозицией и тени фиксированного солнца. Тени используют depth map 1024×1024 и фильтрацию 3×3 PCF в области около камеры. При недоступном shader/FBO движок возвращается к прямому выводу. Пиксели интерфейса и маркеры редактирования сохраняют координаты окна.

- **Ноды геометрии.** Новый редактор графа в прежней теме: Box / Sphere / Cylinder → Transform / Noise / Array / Mirror → Output. Соединение пинов, перемещение узлов, предварительное применение в фоне, проверка циклов и бюджета, сохранение графа и Undo/Redo. Граф содержит до 32 узлов с одним входом геометрии на узел. Preview / Commit сохраняет черновик в объект; Bake оставляет меш для дальнейшего редактирования. Это первые ноды геометрии, без нод материалов и игровой логики.
- **Скульптинг.** Сохранены Inflate / Deflate, Smooth и Flatten; добавлены круг радиуса кисти, симметрия X без двойного воздействия в центре и обновление гладких нормалей после деформации. Нодовый результат можно запечь прямо в панели Sculpt.

## Режимы для разных ПК

| Режим | Масштаб при выборе | Эффекты |
|---|---|---|
| Office | 0.75 | Прямой вывод; кэш отрисовки включён |
| Balanced | 1.00 | FXAA |
| Quality | 1.00 | FXAA, LDR-коррекция цвета и тени солнца |

При первом запуске кэш включён, эффекты выключены, Render scale равен 1.00. Выбор Office через F8 или Settings устанавливает 0.75; масштаб можно изменить отдельно. Интерфейс выводится в разрешении окна, масштабируется только 3D-сцена.

Эффекты требуют дополнительного времени GPU. В отдельном тесте постобработки на программной Mesa, 1280×720, кадр с простым треугольником занимал примерно 0.6 мс при прямом выводе и 10–12 мс с FXAA/LDR. Теневой проход в эти цифры не входит. Это измерение тестовой сцены, без переноса результата на пользовательские GPU. Для слабого видеоядра предусмотрен Office; универсальная частота кадров не заявляется.

## Замеры и проверки

Методика, результаты и команды воспроизведения находятся в `PERFORMANCE.md` и `docs/PERFORMANCE-experimental.md` в ZIP. CSV в этом релизе содержат исходные замеры; файлы `benchmark-*-environment.txt` указывают тестовую ОС, процессор и версии инструментов. Сравниваются существующий C++ путь, прямые Rust-порты и выбранные алгоритмы с учётом C ABI. Выигрыш выбранного алгоритма не приписывается самому названию языка.

Локальные измерения на AMD EPYC 9V74, GCC 14.2, `-O2` (рендер — программная Mesa):

| Операция | 1.0.1 / исходный путь | Эксперимент | Выигрыш |
|---|---:|---:|---:|
| Физический шаг: 3000 статических объектов и персонаж | 4.134 мс | 0.276 мс | 15.0× |
| Физический шаг: персонаж 200 000 вершин и 48 платформ | 30.588 мс | 0.651 мс | 47.0× |
| Weld целиком: 8192 выбранные вершины | 86.269 мс | 13.543 мс | 6.4× |
| Прогретая отрисовка тестового меша, 256×256 | 6.442 мс | 2.631 мс | 2.4× |

Это время отдельных операций, а не ускорение приложения или FPS во всех сценах. Для отрисовки число вызовов тестового меша сократилось с 9025 до одного. Исходные CSV и отдельные измерения CI на Linux/Windows приложены к выпуску; результаты разных машин сравниваются отдельно.

CI проверяет Linux/MinGW с -Werror, нативное выполнение на Windows, Rust-ядро и границу C ABI, соответствие Weld исходной реализации, побитовое соответствие физики, корректность рендера, GL2.1-постобработку, resize и восстановление состояния OpenGL. Продолжаются ASan/UBSan/LeakSanitizer, Lua/MCP, аудиокодеки, Khronos GLB Validator, сохранение проектов и прохождение самостоятельной игры после удаления исходных ресурсов.

Точный SHA проверенной сборки и ссылка на CI добавляются в конец этого отчёта при публикации.

## Файлы и ограничения

`Lunoryx.exe` — Windows x64 редактор; ZIP — редактор, примеры, документация и лицензии; `GemTrail.exe` — самостоятельный пример игры. Rust-ядро подключено статически: для запуска не нужны Rust, Python или компилятор. Контрольные суммы находятся в `SHA256SUMS.txt`.

Минимальная графическая база — OpenGL 2.1 compatibility/FBO. Используются LDR-цвет, простое освещение и AABB-физика. HDR, полноценный PBR, офлайн-рендер и равенство с конкурентными редакторами не заявляются. Производительность зависит от геометрии, материалов, разрешения и GPU; программная Mesa проверяет совместимость и не заменяет испытания на конкретном офисном ПК. Тени Quality охватывают область радиусом около 25 мировых единиц возле камеры; вне карты тень не вычисляется. Используется один фиксированный источник, без каскадов и теней от прозрачности. Карта занимает около 4 MiB плюс память драйвера, добавляет проход геометрии и выборки глубины, поэтому Quality включается по необходимости. Office/Balanced освобождают ресурсы теней. Слишком крупный меш может заполнить бюджет кэша и перейти на запасной путь отрисовки.

Формат проекта schema 2, чтение schema 1, существующие Lua API и игровые контейнеры сохранены. Риг, скелетная анимация, ноды материалов и игровой логики остаются дальнейшим развитием. Lua-скрипты доверенные и имеют доступ к файлам/процессам.

Старый редактор 1.0.1 может показать применённый меш из нового проекта, но при повторном сохранении не сохранит незнакомое поле графа. Для работы с нодами используйте экспериментальную версию и отдельную копию проекта.
